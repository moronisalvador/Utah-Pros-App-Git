# Domain: Auth / Employees / Admin

The platform/infra backbone: employee identity (`employees` is the hub — 89 FKs point at it), the three-layer page-authorization stack (`nav_permissions` role defaults → `employee_page_access` per-employee overrides → `feature_flags` kill-switches, read in exactly that order by `AuthContext.canAccess` and mirrored in SQL by `can_current_employee_access_settings` / `messaging_can_access_conversations`), admin/integration credential management (P9 deny-all pattern), observability stores (`system_events`, `worker_runs`, `upr_mcp_audit`), App-Store account-deletion compliance, and the shared SQL helpers (`mt_today`/`mt_date`, `updated_at` setters). Overall health: all 12 tables are live; the table layer is clean (only 4 dead columns of 101). The RPC layer carries 3 dead functions, 3 duplicates, and a cluster of SECURITY DEFINER functions with no caller check — including a payroll-data family readable by every authenticated user and a clock RPC that accepts an arbitrary employee id. Headline numbers: 12/12 tables used · 61/68 RPCs used (3 dead, 3 duplicated, 1 contract-frozen band-aid) · 8/14 policies sound (6 legacy always-true band-aids) · 1/1 trigger used.

Cross-domain note: `job_time_entries`, `appointments`, `job_tasks`, `jobs`, `contacts`, `estimates`, `invoices`, `sign_requests`, `job_notes`, `tech_feedback`, `notifications`, `google_calendar_links`, `automation_settings`, `message_provider_events` appear inside this domain's function bodies but are owned by other domains — interactions noted, not classified here.

## Structural problems (ranked, worst first)

1. **Clock/task RPCs trust a caller-supplied employee id** — severity 4. `clock_appointment_action` (definer, granted to authenticated) takes `p_employee_id` and never compares it to `auth.uid()` — any logged-in user can clock any employee in/out, altering payroll inputs (`job_time_entries.hours`). Same shape: `toggle_appointment_task` (spoofable `completed_by`), `log_system_event` (arbitrary `actor_id` event forging), `set_contact_owner` (spoofable `p_actor_id`). Violates AGENTS.md §16 (session ≠ authorization); the UI passes the real id, but the server never checks.
2. **Payroll-grade reads are ungated for every authenticated user** — severity 4. `get_timesheet_entries` and dead `get_payroll_summary` (both SECURITY DEFINER, EXECUTE to authenticated, no gate in body) return every employee's hours, hourly_rate, overtime and cost. The `is_time_admin()` predicate exists but gates only the write RPCs; the cross-domain `get_timesheet_entries_admin` is equally ungated (noted for its owner). TimeTracking.jsx:58's "Admin-tier mirrors is_time_admin() server-side" comment is aspirational, not real.
3. **CRM click-to-call logging is silently dead in production** — severity 3. `CrmLeads.jsx:650,1366` do `db.insert('system_events', …).catch(() => {})` as authenticated, but system_events has RLS enabled with ZERO policies → every insert is rejected and the error swallowed. `crm_click_to_call` events have never landed. Fix = route through `log_system_event` RPC or a worker (also restores the worker-writes-audit posture).
4. **`get_claim_activity` joins the wrong actor key** — severity 3. `system_events.actor_id` is FK-constrained to `employees(id)` (fks.json) and SQL writers store employee ids (`set_automation_setting`, `set_contact_owner`, trigger fns), but the RPC joins `employees e ON e.auth_user_id = se.actor_id` — actor_name resolves NULL for FK-conformant rows. The claim activity feed (ClaimPage.jsx) shows anonymous events.
5. **`get_table_stats` is a dynamic-SQL row-count oracle over any table** — severity 2. Definer, EXECUTE to authenticated, `EXECUTE format(… %I, p_table)` — injection-safe but lets any staff member count rows (and read max(created_at)) of ANY public table including messages, contacts, sms_consent_log. DevTools limits the UI list; the RPC doesn't. Gate to admin or pin an allowlist.
6. **P3 anon closure is incomplete on the authz stack** — severity 2. `get_feature_flags` and `get_employee_page_access` still carry EXECUTE to PUBLIC+anon (functions-meta acl), and always-true anon read policies remain on feature_flags (`anon_read_flags`), nav_permissions (`nav_permissions_anon_read`), employee_page_access (`anon_read_employee_page_access`). All bootstrap reads verified post-auth (AuthContext:1037-1048) — the anon legs have no consumer and contradict the database-standard §1 posture; §2's "login/session bootstrap" cover no longer applies.
7. **Account-deletion fulfillment loop was never built** — severity 2. Requests insert + admin notifications work, but nothing anywhere updates `status`/`actioned_by`/`actioned_at` (zero writers; columns dead; `account_deletion_requests_admin_update` policy dormant). App Store compliance currently ends at "recorded", with fulfillment presumably manual and unaudited.
8. **Observability tables: unbounded growth + redundant broad grants** — severity 1. worker_runs (9,975 ins, 1 del, pkey-only index — every `get_worker_runs` call seq-scans) and upr_mcp_audit (3,089 ins, no retention) grow forever. Secrets tables (integration_config/credentials, user_google_accounts) still carry full table grants to anon/authenticated under the RLS deny-all lid — one accidental `DISABLE ROW LEVEL SECURITY` from exposure; revoking the unused grants is free belt-and-suspenders.
9. **The page-authz decision exists in two implementations** — severity 1 (by design, but a drift risk). JS: AuthContext.canAccess (override → admin → role default, flags separate). SQL mirrors: `can_current_employee_access_settings` (settings), `messaging_can_access_conversations` (conversations) re-implement the same cascade per page. Triple-gating itself is coherent (nav_permissions = role default, employee_page_access = override, feature_flags = kill-switch — the router genuinely reads all three), but each new SQL-gated surface hand-copies the cascade.
